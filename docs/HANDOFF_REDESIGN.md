## 3. 絵のきまり（全員が守る）

### 大きさと見る角度
- 1マス＝横24×縦（奥行き）18ドット。高さ1ドット＝16/16で、縦方向そのまま（見る角度48°）。`js/dotart.js` の `TW=24, TD=18, HU=16`。
- 画面はバッファ312×298ドットを拡大する。iPhone幅393pxなら、1ドット≒1.26px、1マス≒30×23px。
- **タワー**
  - 足もとの幅は**22ドット以内**（となりのマスにはみ出さない）
  - 高さは段階0で約30〜40ドット、段階2で最大約50ドット
  - いちばん上の行に置いても、上の余白（OY=22）から大きくはみ出さないこと（てっぺんが画面の外に出ない）
- **道に置く物**（金鉱・トゲの罠・粘着の沼・爆弾樽・バリケード）：低くて平たい。高さ12ドット以内。
- **敵**
  - ふつうの敵：幅10〜16、高さ12〜22ドット
  - 大きい敵（オーク・騎士・イエティなど）：幅16〜20、高さ20〜28ドット
  - ボス：幅24〜36、高さ28〜40ドット
  - 空を飛ぶ敵は、絵の下に余白を作らない（浮かせるのは描く側の `render.js`）

### 描き方
- 光は**左上から**。立体は「上の面＝明るい・手前の面＝ふつう・右の端＝影・左の端＝ハイライト・下の線＝暗い」。`dotart.js` の `box`（四角い台）、`cyl`（円柱）、テストページの `stack`（台の積み重ね）、`crystal`（水晶）を使う。
- **黒いふち取りはしない**（背景と同じく、色の明るさの差で形を出す）。下の線だけ暗くする。
- 影の楕円は絵に入れない（`render.js` が描く）。例外は砦。
- 1つの絵の色は**12色くらいまで**。地域（草原・雪山・火山）のどの地面の上でも見えること。
- 色の決まり：
  - 石：`#807d78` 系
  - 木：`#8d6034` 系
  - 鉄：暗い青灰色
  - 金の飾り：`#e8c040`
  - タワーごとの「目印の色」は今の絵と同じにする（弓＝緑の服と木、炎＝赤とオレンジ、氷＝水色、雷＝銅と青、毒＝緑、魔導士＝紫、大砲＝黒い鉄など）
- **段階（Lv1〜3）の見分け方**（全タワーで共通）
  - 段階0：土台が石か木だけの素朴な形
  - 段階1：屋根や鉄の補強が増えて、少し高くなる
  - 段階2：金の飾りと旗がつき、いちばん高い
  - 今の絵は旗の色（赤→青→金）で段階を表しているので、旗の色は残してよい
- **攻撃中の絵（fire=1）**：ふだんの絵から「弦を引く」「砲口が光る」「水晶が明るくなる」など1〜3か所だけ変える。形は変えない（位置がずれて見えないように）。
- **左右の向き**：今 `.l` と `.r` があるタワー（大砲・弩砲など、向きのある物）は新しい絵でも作る。敵は全員、右向きを描いて左右反転で左向きを作る。

### コードの決まり
- 新しい絵は `js/towerart.js`（タワー）と `js/enemyart.js`（敵・兵士）に書く。`dotart.js` の道具（`G.DotArt.mk/R/ell/box/cyl`）を使う。`index.html` で `dotart.js` のあと、`render.js` の前に読み込む。
- できた絵は、今と同じ形で `G.SPR` に入れる。こうすれば `render.js` や画面のほかの所の変更が少なくて済む。
  - タワー：`G.SPR[種類][段階0〜2][0＝ふだん/1＝攻撃中]` に canvas。向きがある物は `{ l: canvas, r: canvas }`
  - 敵：`G.SPR[種類][コマ0/1] = { l, r }`
  - **canvas の下のふち＝足もと（土台の手前の下の線）**、横の真ん中＝タワーの中心、にそろえる
- 古い絵の関数（`sprites.js` のタワー・敵）は、新しい絵が全部そろってから消す。
- コメントは日本語で、高校生が分かる言葉で書く。素のJavaScriptだけ（ライブラリなし）。

## 5. 作業の順番と、まとめ方

### 段階② タワー
1. **［Opus］共通の部品**を `js/towerart.js` に作る：石の台・木の台・円柱・屋根（三角・円すい）・旗・金の飾り・段階の積み上げ。

   - 1回目：`bowman, sling, watch, dart, sniper`（弓・投石・見張り系）
   - 2回目：`fire, thunder, poison, mage, storm`（魔法系）
   - 3回目：`mortar, ballista, blizzard, barracks, golem`（大型・兵士を出す系）
   - 4回目：`mine, spikes, tar, barrel, barricade`（道に置く物。平たい）
   - 毎回、係が一覧画像を作る → Opus が見て、直しを同じ係かもう1回の依頼で出す（**直しの依頼は1回の束につき最大1回**。それでも直らない所は Opus が自分で直す）。
   - 2回目のあとで**チェックポイントC2**。
5. 全部そろったら、古いタワーの絵の関数を消し、一覧画像・3地域の戦闘画面で確認 → SPEC更新 → commit・push → **チェックポイントC3**。

3. **［Sonnet係］残りを6体ずつ**：
   - ふつうの敵

   - ボス
   - 兵士・石の巨人
4. 全部そろったら確認 → SPEC更新 → commit・push → **チェックポイントC5**。

### 段階④ 弾・効果・文字
- テストにある物はテストの数字。無い物は古い数字×1.5（射程の点の数、弾の大きさ、粒の速さ・重さ、画面のゆれ、数字・ハートの位置、3×5の数字）。
- 画面を撮って不自然な所だけ直す → SPEC更新 → commit・push → **チェックポイントC6（終わり）**。

## 7. チェックポイント（使用量の確認と、方針の助言）

**前提**
- オーナーの週の使用量は、引き継ぎ時点で **57%**。**90%までに終える**のが目標で、使えるのは約33ポイント。
- Claude からは使用量が見えないので、各チェックポイントで**オーナーに％を聞く**。
- **目安の配分**（実際に使った量で毎回見直す）：
  - 段階②タワー：約15
  - 段階③敵：約11
  - 段階④：約3
  - 予備：約4

| 点 | タイミング | Claude がすること |
|---|---|---|
| C0 | 新しい会話の最初 | ％を聞いて記録する |
| C1 | タワー見本3種と組み込みが終わった時 | 画面を見せて、見本の出来の判断をもらう。％を聞き、C0からの増え方を出す |
| C2 | Sonnet係の2回目（10種）が終わった時 | ％を聞き、「1種あたりの使用量」を計算し、残り全部（タワー10種＋敵29体＋④）の見込みを出す |
| C3 | タワー全部が終わり push した時 | 同じく見込みを出し直す。敵の進め方を決める |
| C4 | 敵の見本3体が終わった時 | 画面を見せて判断をもらう。％と見込み |
| C5 | 敵全部が終わり push した時 | ％と見込み。段階④をどのモデルでやるか決める |
| C6 | 全部終わった時 | 最終の％と、やり残し |

### 助言のしかた
各チェックポイントでは、次の4つを短く出す。
- 今の％
- 増えた量
- このままの見込み（何％で終わりそうか）
- 次の進め方

見込みが90%を超えそうな時は、**質が下がりにくい順**に次の手を出し、オーナーに選んでもらう。オーナーは「方針の助言もしてほしい」と言っているので、どれがよいかの意見も添えてよい（ただし事実・数字・弱い点も必ず並べる）。

1. **確認をまとめる**：Opus の確認を「1束ごと」から「2束ごと」に減らす（一覧画像を見る回数が半分になる）。
2. **色ちがいを増やす**：形が同じ種類の敵・タワーを、色ちがいの関数でまとめる（描く量が減る）。
3. **メインを Sonnet に**：段階④をメインごと Sonnet で行う。オーナーに `/model claude-sonnet-5-5` を頼む。
4. **段階④を来週に回す**：弾・効果は古いままでも遊べる。
5. **段階を共通にする**：段階0〜2の形を共通にして、飾りの色だけで見分ける（質は下がる）。

見込みに余裕がある時（75%以下で終わりそう）は、次を出してよい。
- 見本を1つ増やす
- 直しの回数を増やす

## 8. Opus が確認する時の見る所（一覧画像・戦闘画面）

- **形**：遠くから（1マス≒30px）でも、どのタワー・敵か形で分かるか。目印の色は出ているか。
- **光**：光の向き（左上）、上の面・手前の面・右の影がそろっているか。黒いふち取りが混ざっていないか。
- **大きさ**：幅22ドット以内。となりのタワーと重ならないか。いちばん上の行で上にはみ出しすぎないか。
- **段階**：段階0→1→2で、高さと飾りが増えて見分けられるか。
- **攻撃中の絵**：位置がずれていないか（ガタつかないか）。
- **地域**：草原・雪山・火山のどの地面でも見えるか（特に雪の上の白っぽい物、火山の上の暗い物）。
- **小さな絵**：カード・デッキ画面・ショップの小さな絵が、はみ出したり、つぶれたりしていないか。
- **数字**：自動対戦 `node tools/sim.js 5` の勝ち数が大きく変わっていないか（絵だけの変更なので、同じになるはず。今は 10/15）。
