## 1. ゲームの概要

- ジャンル：デッキ構築型ローグライク × タワーディフェンス（スレイザスパイアの進行 ＋ キングダムラッシュの戦闘）
- 1人用
- 遊ぶ環境：スマホのブラウザ（iPhone Safari を基準）。PCブラウザでも遊べるようにする
- 公開先：Cloudflare（無料プラン）。コードは GitHub で保管し、更新すると自動で公開ページに反映する
- 目指す楽しさ
  - キングダムラッシュ：強くなっていくインフレ感、自分で考えた最強構築で戦っている感覚
  - エンバーワード：組み合わせの構築を考える楽しさ
- 「忙しすぎてしんどい」を減らすため、敵が来ない準備ターンを挟む

## 2. 画面と操作

- **縦持ち**で固定（横持ちは対応しない。横にされたら「縦にしてください」と表示）
- 画面上部〜中央：マップ（斜め見下ろしのドット絵）
- 画面下部：手札
  - 基本4枚、最大8枚
  - 4枚までは1段、5枚以上は2段（4枚×2段）
  - カード1枚の幅は約85pt以上（Appleの推奨タップ範囲44ptを大きく上回る）
  - 配置は「カードをタップで選択 → マップ上の置き場所をタップ」の2段階（誤タップ防止）。ドラッグでの配置も可
  - 長押しでカードの詳細表示（Safariの長押しメニュー・文字選択は無効化する）
- スタート画面：「上にスワイプしてスタート」
  - このスワイプでSafariのアドレスバーを細く縮める（ゲーム側から自動では縮められないため）
  - 縮まらなかった場合でも遊べるよう、アドレスバーが出ている前提の配置にしておく
  - 画面の上端・下端付近には大事なボタンを置かない（触るとアドレスバーが戻ることがあるため）
- ホーム画面への追加は必須にしない（任意で案内するだけ）

## 3. 見た目と音

- 表現：**ドット絵**（コードで1ドットずつ生成。画像ファイルは使わない）
  - 320×213ドット前後の小さな画面に描いて拡大表示（縦持ち用に比率は要調整）
  - キャラ・タワーは起動時に絵を作り置きし、コマ切り替えで動かす
  - 参考：サンプル「オーク対魔導士 ドット版」
- BGM・効果音：**コードで合成**するのが基本（ファミコン風の電子音）
  - 外部で作った曲を入れる場合は1曲ずつ別ファイルにし、その場面で必要な曲だけ読み込む（20曲で約20〜40MB）

## 4. 世界観（仮・後で変更の可能性あり）

- 一般的なファンタジー
- 味方：人型のいろいろな種族（人間、エルフ、ドワーフなど）と職業（戦士、魔法使い、魔剣士、ウォーリア、バーサーカーなど）
- 敵：よくある敵（スライム、ゴブリン、オーク、ドラゴンなど）
- ゲーム名：未定

## 5. 1回の挑戦（ラン）の流れ

- 長さ：1ラン1時間ちょっと。途中セーブ込みで2〜3時間も可
- マップ選択はスレイザスパイア式（分かれ道を選んで進む）
  - マスの種類：戦闘、エリート戦（強敵）、イベント、商人、強化・回復、ボス
  - マス数・階層数：未定（1ラン約1時間に収まるよう調整）
- 戦闘に勝つと報酬
  - 3つの中から1つ選ぶ（タワー、兵士、兵器などのカード）
  - 中ボス・エリート撃破でレリック
- 負け条件：拠点のライフ制。ゴールまでたどり着いた敵の数（または種類ごとの値）だけライフが減り、0で負け
  - 特殊ボスで条件を変えることは現時点では予定なし

## 6. 戦闘のルール

### 6.1 ターンの流れ

1. **準備ターン**（敵は攻めてこない）
   - 次の攻撃で「どこから・どの敵が・何体」来るかが見える
   - 手札を4枚引く（無料）
   - タワーを建てる、強化する
2. **攻撃ターン**（敵が攻めてくる）
   - 攻撃中もリソースを使って建築・強化ができる
   - 一定の条件を満たすと、攻撃中もカードを追加で引ける（例：特定のタワーやレリックの効果）
3. 1と2をくり返し、最後の攻撃をしのげば勝ち

### 6.2 リソース（2種類）

| リソース | 増え方 | 主な使い道 |
|---|---|---|
| エネルギー | 毎ターン一定量回復（スレスパ式） | タワーを建てる（カードを使う） |
| お金 | 敵を倒すと増える（キングダムラッシュ式） | タワーの強化、追加ドロー |

- 毎ターンの4枚ドローは無料
- 数値（回復量・コスト・報酬額）は試作で調整

### 6.3 デッキとカード

- 初期デッキ ＋ 道中の3択報酬で拾ったカード（スレスパ式）
- 山札 → 手札 → 捨て札 → 山札がなくなったら捨て札を混ぜて山札に戻す
- 置いたタワーのカード
  - 基本：タワーは盤面にずっと残り、カードは捨て札へ（次に引いたらもう1基建てられる）
  - 例外（カードごとの特性）：その戦闘中はデッキから消える／一定ターンで消える　など

### 6.4 配置場所

- 2つの方式を検討中（試作で比較して決める）
  - (a) 決まった台座だけに置ける（キングダムラッシュ式）
  - (b) 道以外の好きなマスに置ける
- (b) は、敵の通り道を変える要素がなければ大きな手間はかからない。「置いた物で道がふさがる」仕組みを入れると手間が増える

### 6.5 マップ

- 分かれ道・複数ルートあり
- 敵の出現口が複数ある戦闘あり

### 6.6 足止め役（兵士）

- ときどき入れたい。入れ方は要相談。候補：

| 方式 | 内容 | 開発の手間 |
|---|---|---|
| 障害物カード | HPのある「止めるだけの物」（バリケードなど）を置く | 低 |
| 足止めカード | 指定地点に兵士が数ターン立つ。倒れたら終わり | 中 |
| 兵舎タワー | 道に兵士を出し、倒れても復活する（キングダムラッシュ式） | 高 |

- 段階3でまず障害物カードから入れる

## 7. レリック

- 2種類とも入れる
  - 数値型：攻撃力+10%、エネルギー+1 など
  - 変化型：遊び方そのものを変える（例：「タワーを建てるたびにカードを1枚引く」など）

## 8. セーブ

- ランの中断・再開ができる（ブラウザ内に保存）
- 負けたらそのランは終了（やり直し不可）
- 解放要素あり（新しいカード・キャラなどがランをまたいで解放される）。内容は未定

## 9. 開発の進め方

| 段階 | 内容 | 完了の目安 |
|---|---|---|
| 0 準備 | この仕様書、GitHub と Cloudflare の連携 | 自分のURLでサンプルが開ける |
| 1 戦闘の試作 | マップ1枚・タワー3種・敵3種・準備/攻撃ターン・手札4枚・上スワイプ開始 | 1戦が最後まで遊べる |
| 2 ランの骨組み | 分かれ道マップ、3択報酬、デッキの循環、商人・休憩・イベント | 短縮版の1ランが通しで遊べる |
| 3 深み | レリック、ボス、足止め役（障害物から） | 構築の違いで戦い方が変わる |
| 4 保存と音 | 中断・再開、解放要素、BGM・効果音 | 続きから遊べる |
| 5 量産と調整 | 敵・タワー・レリックを増やす、自動対戦でバランス確認、身内テスト | 1ラン約1時間 |
| 6 一般公開 | 公開ページ整備、必要ならランキング（Cloudflare D1） | 誰でも遊べる |

- 各段階の区切りで、別のAIによる確認（サブエージェント）を必要に応じて使う
- 段階ごとに新しいチャットで始め、この仕様書を読み込ませる

## 10. 技術メモ

- 素のHTML・CSS・JavaScript（ゲームエンジンは使わない）
- ファイルは役割ごとに分ける（データ／描画／戦闘処理／画面）
- 縦持ち画面の高さは、アドレスバーの状態に合わせて変わる指定（dvh）で合わせる
- 長押しメニュー・文字選択・ダブルタップ拡大を無効化する
- 参考資料
  - iPhone Safari は全画面表示・向きの固定に非対応（2026年10月時点）：https://caniuse.com/fullscreen 、https://caniuse.com/wf-screen-orientation-lock
  - アドレスバーはユーザーが下にスクロール（指を上に動かす）した時だけ縮む：https://www.macrumors.com/guide/ios-26-safari-features/
  - タップ範囲の推奨（Apple 44pt）：https://specification.website/spec/accessibility/touch-target-size/
  - Cloudflare Pages 無料プランの制限：https://developers.cloudflare.com/pages/platform/limits
