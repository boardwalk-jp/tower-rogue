## 2. 画面と操作

- **縦持ち**で固定（横持ちは対応しない。横にされたら「縦にしてください」と表示）
- 画面上部〜中央：マップ（斜め見下ろしのドット絵）
- 画面下部：手札
  - 基本4枚、最大8枚
  - 4枚までは1段、5枚以上は2段（4枚×2段）。2段の時は2段目が1段目に重なり、1段目は上の36px（コストと名前）だけ見える
  - カード名とコストはカードの上部（重なっても見えるように）
  - 手札の枚数でマップの大きさは変わらない（いつも2段分の高さを見込んでマップの大きさを決める）
  - カード1枚：幅は約85pt、高さ76px。1段目の見えている部分（36px）はAppleの推奨タップ範囲44ptより小さい
  - 配置は「カードをタップで選択 → 置き場所をタップ（仮置き：射程が見える）→ 同じマスをもう一度タップで建設」。別のマスをタップすると仮置きが移動する（誤タップ防止）
  - ドラッグでも置ける。離した場所が仮置きになり、確定はタップ
  - 長押しでカードの詳細表示（Safariの長押しメニュー・文字選択は無効化する）
  - エネルギーは手札のすぐ上に表示（カードのコストと見比べやすくするため）
  - 同じ段に山札・捨て札の枚数とアイコン。タップすると内訳（カードの種類ごとの枚数）が出る。山札は引く順番が分からないよう、種類と枚数だけ
  - お金で1枚引くボタンの表記は「ドロー」
  - 攻撃中の残りの敵の数は画面上部の帯に出す（マップ下の説明の行は削除）
- 置いたタワーをタップすると小窓が出る（閉じるボタンなし。小窓の外をタップすると閉じる）
  - 「狙う敵」ボタン：タップするたびに 先頭 → 最後尾 → 体力が多い → 体力が少ない → 近い → 遠い と切り替わる（最初は先頭）。射程の中の敵から選ぶ。近い・遠いはタワーからの距離
- タワーを置くカードを選んでいる間は、置いてあるタワーを半透明にし、タワーの絵をタップしても小窓を開かない（後ろのマスに置こうとして手前のタワーを開いてしまう誤タップへの対策、2026-10-18）。タワーを選びたい時はカードの選択を外す
- 速度：×1 → ×2 → ×4 の切り替え
- 報酬・商人・カードを手放す画面では、カードをタップすると詳細（説明・数値・ランク）が出る
  - 強さは表で表示：1行＝1項目（攻撃力・射程・攻撃速度・爆発範囲）、左から「項目名｜今の値｜太い矢印｜強化後の値」。矢印は全行で1本（行の真ん中）で、上に「強化後」と書く。「今」という見出しの行はない
  - 強化後の値の後ろに差を書く（例：10 E (+4)）。数値そのものは色を変えず、差だけ色を付ける
  - 最大まで強化済みのタワーは、矢印と強化後の列を出さない
  - マップ上に今の射程（白）と強化後の射程（アップの赤、縮む場合はダウンの青）を表示。強化ボタンもアップの赤
- **アップ・ダウンの色（ゲーム全体で統一）**
  - アップ（強くなる）＝赤 `#ff5b4a`、ダウン（弱くなる）＝青 `#4ea8ff`。`js/data.js` の `G.UP_COLOR` / `G.DOWN_COLOR` と CSS の `--up` / `--down`
  - 数値が増えたか減ったかではなく「強くなったか弱くなったか」で色を決める（今の表示項目はすべて「大きいほど強い」）
- **数値のランク**（タワーの小窓・カードの詳細で、数値の後ろに小さな札で表示）
  - 数値ごと（攻撃力・射程・攻撃速度・爆発の広さ）に、全タワーの Lv1〜最大強化の通常の値から「最大〜最小」を出し、等間隔で6つに区切って上から S・A・B・C・D・E
  - 境目ちょうどの値は上のランク
  - レリックなどの効果で通常の最大を超えたら、同じ間隔で1段ごとに SS・SSS（それ以上もSSS）。最小を下回ったら F・G（それ以下もG）
  - その数値を持つタワーが1種類だけならランクを付けない（今は爆発の広さ＝大砲だけ）
  - 攻撃力は数字をそのまま比べる（魔法・範囲攻撃の強さは入れない）
  - タワーの追加や数値の変更をすると、自動で計算し直される（`G.Rank.build()`）。そのため既存タワーのランクが変わることがある
  - ランクの札の色は金・灰系
  - 強化後のランクが変わる時は、札の前に矢印を付ける（上がる＝赤の↑、下がる＝青の↓）。札もその色にする。ただし新しいランクがA以上なら札は金色のまま（矢印だけ色付き）。変わらない時は矢印なし
- **攻撃速度の表記**：「1.25発/s」（1秒あたりに撃つ数、小数2けた）。データは「何秒に1回撃つか」で持ち、表示の時に 1 ÷ 間隔 で直す
  - 強化ボタン、強化後の射程、強化値は赤。弱体値、射程の縮小は青。今後の強化・弱体（レリック、状態異常など）もこの2色を使う
- スタート画面：「上にスワイプしてスタート」
  - このスワイプでSafariのアドレスバーを細く縮める（ゲーム側から自動では縮められないため）
  - 縮まらなかった場合でも遊べるよう、アドレスバーが出ている前提の配置にしておく
  - 画面の上端・下端付近には大事なボタンを置かない（触るとアドレスバーが戻ることがあるため）
- ホーム画面への追加は必須にしない（任意で案内するだけ）

## 5. 1回の挑戦（ラン）の流れ

- 長さ：1ラン1時間ちょっと。途中セーブ込みで2〜3時間も可
- マップ選択はスレイザスパイア式（分かれ道を選んで進む）
  - マスの種類：戦闘、エリート戦（強敵）、イベント、商人、強化・回復、ボス
  - マス数・階層数：未定（1ラン約1時間に収まるよう調整）
- 戦闘に勝つと報酬
  - 3つの中から1つ選ぶ（タワー、兵士、兵器などのカード）
  - 中ボス・エリート撃破でレリック
- 負け条件：拠点のライフ制。ゴールまでたどり着いた敵の数（または種類ごとの値）だけライフが減り、0で負け
  - 特殊ボスで条件を変えることは現時点では予定なし

## 6. 戦闘のルール

### 6.1 ターンの流れ

1. **準備ターン**（敵は攻めてこない）
   - 次の攻撃で「どこから・どの敵が・何体」来るかが見える
   - 表示方法：次に使われる入口に「！」が出て、タップするとその入口から来る敵の種類と数が吹き出しで出る（常時表示はしない）
   - 手札を4枚引く（無料）
   - タワーを建てる、強化する
2. **攻撃ターン**（敵が攻めてくる）
   - 攻撃中もリソースを使って建築・強化ができる
   - 一定の条件を満たすと、攻撃中もカードを追加で引ける（例：特定のタワーやレリックの効果）
3. 1と2をくり返し、最後の攻撃をしのげば勝ち

### 6.2 リソース（2種類）

| リソース | 増え方 | 主な使い道 |
|---|---|---|
| エネルギー | 毎ターン一定量回復（スレスパ式） | タワーを建てる（カードを使う） |
| お金 | 敵を倒すと増える（キングダムラッシュ式） | タワーの強化、追加ドロー |

- 毎ターンの4枚ドローは無料
- 数値（回復量・コスト・報酬額）は試作で調整
- 試作の仮ルール：準備ターンの始めに、前のターンの手札は全部捨て札へ（スレイザスパイア式）。エネルギーも持ち越さない

### 6.3 デッキとカード

- 初期デッキ ＋ 道中の3択報酬で拾ったカード（スレスパ式）
- 山札 → 手札 → 捨て札 → 山札がなくなったら捨て札を混ぜて山札に戻す
- 置いたタワーのカード
  - 基本：タワーは盤面にずっと残り、カードは捨て札へ（次に引いたらもう1基建てられる）
  - 例外（カードごとの特性）：その戦闘中はデッキから消える／一定ターンで消える　など

### 6.4 配置場所

- **決定（2026-10-18）：道以外の好きなマスに置ける**（台座式は試遊のうえ不採用）
- 置けないマス：道、木、岩、砦の敷地、すでにタワーがあるマス
- 「置いた物で道がふさがる」仕組みは入れない
- 今後の検討：道にだけ置ける建物（トゲなどの罠）→ 14章

### 6.5 マップ

- 分かれ道・複数ルートあり
- 敵の出現口が複数ある戦闘あり

### 6.6 ダメージの数字

- 敵に当たるたびにダメージの数字が出る（拡大後の画面に文字で描く）
- 色で種類を分ける

| 種類 | 色 | 例 |
|---|---|---|
| ふつう | 白 | 弓・大砲がよろいのない敵に当たった、魔法 |
| 減った（よろい・耐性） | 灰色がかった青、少し小さく | 弓・大砲がオークに当たった |
| 毒（今後） | 黄緑 | 毒の継続ダメージ |
| やけど（今後） | オレンジ | 炎の継続ダメージ |

- 倒した時のお金は黄色で「+3」などと出る

### 6.7 足止め役（兵士）

- ときどき入れたい。入れ方は要相談。候補：

| 方式 | 内容 | 開発の手間 |
|---|---|---|
| 障害物カード | HPのある「止めるだけの物」（バリケードなど）を置く | 低 |
| 足止めカード | 指定地点に兵士が数ターン立つ。倒れたら終わり | 中 |
| 兵舎タワー | 道に兵士を出し、倒れても復活する（キングダムラッシュ式） | 高 |

- 段階3でまず障害物カードから入れる

## 7. レリック

- 2種類とも入れる
  - 数値型：攻撃力+10%、エネルギー+1 など
  - 変化型：遊び方そのものを変える（例：「タワーを建てるたびにカードを1枚引く」など）

## 8. セーブ

- **自動セーブ（2026-10-18 実装）**：ブラウザの中（localStorage）に1つだけ保存。保存するタイミング：
  - ワールドマップに戻った時
  - マスに入る時（途中でやめると、つづきからは同じマスに入り直す。戦闘は最初からやり直し。イベント・商人の中身は同じ）
  - 戦闘に勝って報酬が出た時（つづきからは同じ3枚の報酬選びから）
  - イベントの選択肢・たき火を選んだ直後（つづきからはマップへ）
- タイトル画面で「つづきから」「はじめから」を選んでから、上にスワイプで開始。つづきからには「何階・ライフ・デッキ枚数・保存日時」を表示。保存がない時は押せない
- 「はじめから」を選んで始めると、前の保存は消える（選んだ時に注意書きを出す）
- ワールドマップの「メニュー」→「タイトルに戻る」。ランの終わり画面からもタイトルに戻れる
- 負けたら・クリアしたら保存は消える（やり直し不可）
- 注意：保存は同じ端末・同じブラウザの中だけ。Safariの履歴やWebサイトのデータを消すと消える。チャット内の表示と、Cloudflareで公開したページは別の保存場所になる
- データを消されにくくするお願い（2026-10-20）：上にスワイプで始める時（タップの操作の中）に、ブラウザへ「このサイトのデータは消さないで」とお願いする（`navigator.storage.persist()`・Safari 17以降）。許可するかはブラウザが決める。結果は `towerRogue.persist`（1＝許可／0＝不許可）に記録するだけで、画面には出さない。許可されていなければ、始めるたびにもう一度お願いする。背景：Safariは、しばらくそのサイトを操作しないとデータを消すことがある（WebKit公式ブログ）。ホーム画面に追加したアプリは数え方が別で、消されるとは考えていないと書かれている。セーブの書き出し・読み込みは下に書いた通り実装済み
- データの引き継ぎ（2026-10-20）：経験値・解放・クリアの記録（`towerRogue.meta.v1`）と最後に選んだ難易度を、「TR1:」で始まる文字にして書き出す／読み込む。途中のラン（つづきから、`towerRogue.save.v1`）は2026-10-22から `save` として含める（ある時だけ。古い文字もそのまま読める。壊れた save は途中のランだけ無視）。読み込むと今の途中のランは置きかわる（文字に save が無い時は今のまま残す）。旧URL（GitHub Pages）から新URL（syoppaiya-td.pages.dev）への移行に使う（13.56）。読み込みは今の記録を上書きするので、1回目は確認の文を出し、もう一度押すと実行する。形が違う文字・数字でない値は読み込まない。メニューは、タイトル右上の「メニュー」（効果音・BGM・遊び方・データの引き継ぎ）と、ワールドマップのメニューの「データの引き継ぎ」の2か所から開く
- データの引き継ぎの不具合直し（2026-10-20）：①貼り付けで「TR1:」が小文字・全角になっても、空白・改行・引用符が入っても読み込めるようにした（文字の本体は大文字小文字を区別するので、頭の「TR1:」だけ大小を問わない）。入力欄は自動の大文字化・自動修正を切った。②メニュー・データの引き継ぎを開いている間は、タイトルの「スクロールで始める」を働かせない（キーボードで画面がずれて、後ろでゲームが始まっていた）。③入力欄の文字を16pxにした（iPhoneは小さい文字の欄に入力すると画面を拡大する）。④入力欄では、文字の選択・長押しメニューを止めない（それまでは全体で止めていたため、長押しコピー・貼り付けが働かない可能性があった）。⑤開いている画面の中のスクロールを、後ろの画面に伝えない
- カード選び画面の「やめる」（2026-10-20）：カードをタップして詳細が出ている時は、「やめる」で選ぶ前のカード選びに戻る（選択を外す）。何も選んでいない時の「やめる」は今まで通り、前の画面（たき火のメニューなど）に戻る。たき火の「鍛える」「整理する」、商人・イベントのカード選びすべてで同じ
- 音量（2026-10-20）：基礎音量を上げた（効果音0.32→0.45、BGM0.12→0.18、ボス曲0.55→0.8。約1.4〜1.5倍）。ワールドマップのメニューとタイトルのメニューに、効果音とBGMの音量バーを付けた（0〜100、標準50、100で標準の2倍）。オン/オフのボタンはそのまま。音量はこのブラウザに覚え（`towerRogue.sound` の `seVol`・`bgmVol`）、つづきから・次に開いた時も引き継ぐ。データの引き継ぎには含めない。効果音の音量バーは、指を離した時に今の大きさで1回鳴らす
- 記録を守る案内：タイトルの「記録を消さないために」（太字）と、遊び方の末尾の同名の項目から開く。iPhone（Safari）と Android（Chrome）の「ホーム画面に追加」の手順、ホーム画面から遊ぶと記録が分かれることがある注意、別の端末・ブラウザへ移す方法と「データの引き継ぎ」へのリンクを書く。Android側は、Chromeが「インストール済みか・ブックマーク済みか」を目安に消さない扱いにすると書かれている（web.dev）
- 解放要素あり（新しいカード・キャラなどがランをまたいで解放される）。内容は未定

- ファイルは役割ごとに分ける（データ／描画／戦闘処理／画面）

- 長押しメニュー・文字選択・ダブルタップ拡大を無効化する
  - iPhone の Safari は viewport の「拡大しない」指定を無視するため、JSでも止める：0.35秒以内の2回目のタップは拡大させず、代わりにタップとして扱う（2026-10-19 に実機で拡大して戻せない不具合が発生）。それでも拡大された時は、2本指のピンチで戻せるようにし、画面の設定を書き直して元の大きさに戻す
  - 右端が見切れる対策（2026-10-19）：`html, body` に `overflow-x:hidden`。横にずれていたら位置を0に戻す。拡大を見つけたら、画面の設定を一度ちがう値に書きかえてから戻して倍率を1に戻す（読み込み時・タップの後・画面の大きさが変わった時に確認）
- スマホが前の版のCSS・JSを使い回して表示がくずれることがあるため、`index.html` の読み込みに `?v=日時` を付ける。ファイルを変えて公開する前に `python3 tools/stamp.py` を実行する（2026-10-18 に実機で発生）

## 12. 経緯と判断の理由（前のチャットでのやり取りの要点）

新しいチャットに引き継ぐときに、決定の「理由」や「やらないと決めたこと」が抜けないように残す。

### 12.1 見送った案とその理由

- **3D（ローポリ）**：スマホでは処理が重く、見下ろし視点だと小さい敵が見分けにくい。攻撃などの動きも真上からだと分かりにくい
- **図形で描く疑似3D**：細部を描き込んだ版を作ったが、オーナーの評価は「ドットの方が雰囲気がいい」。また同じ環境の比較で、図形版は50体で約23コマ/秒、ドット版は400体でも60コマ/秒（1コマ6.2ms）と、ドット版の方が大人数に強かった
- **横持ち**：iPhoneのSafariは全画面表示と向きの固定に非対応（2026年10月時点）。ホーム画面への追加をユーザーに求めたくないため縦持ちにした
- **手札8枚の横一列**：1枚の幅が約41ptになり、Appleの推奨（44pt）を下回る。4枚×2段なら約87pt

### 12.2 オーナーの考え・こだわり

- 好きなタワーディフェンスはキングダムラッシュとエンバーワード。「自分の考えた最強構築で戦っている感」「組み合わせを考える楽しさ」が軸
- タワーディフェンスは忙しさが良さでもあり、しんどさでもある → 準備ターンを挟む形にした
- 「モンスタートレインに近くなるのでは？」という懸念が一度出ている（デッキ構築×防衛のため）。比較は未実施。違いを出したい時はここに立ち返る
- 足止め役（兵士）は、オーナーは「開発の手間を気にせず考えたい」とのこと。手間の大小は伝えたうえで一緒に決める
- 外部素材はできるだけ使わず、コードだけで作りたい。ただし分かりやすさ（何がいるか一目で分かる）は必須
- 公開は「最初は小さく、一般にも開放してみたい」

### 12.3 確定した細かい仕様と注意点

### 13.17 勝利の曲・続きから遊んだ時の音（2026-10-19）

- **勝利の曲**：ボス戦に勝った瞬間から、明るいファンファーレ（`victory`、ハ長調・1分間120拍）をくり返す。報酬の画面・層クリアの画面の間も流し、次の層のワールドマップに入ると層の曲に戻る。ラスボスに勝った後の終わりの画面でも流す。「つづきから」で報酬・層クリアの画面から再開した時も流す

  - 原因（考えられるもの）：「つづきから」は最初から選ばれているので、タップせずに上にスワイプだけで始まる。スワイプの終わりはブラウザにタップとして認められないので、その時に作った音の準備が止まったままになっていた

  - 2026-10-19 02:40 実機で効果音・BGMが全く鳴らなくなった（02:32の版）。考えられる原因：1回のタップで pointerup・touchend・click が続けて来て、そのたびに音の準備を作り直していた／`navigator.userActivation` の判定が iPhone では思った通りに働かない。直し方：音の準備は touchend（指が12px以上動いたスワイプは除く）・click・キー入力の中だけ、プログラムが出したクリックは使わない。作り直しは「前のタップで再開を試してから0.8秒以上たっても止まったまま」の時だけ・最大3回
  - 「音のテスト」に、音の準備の状態（running など）・作り直した回数・ページで起きたエラーを出す
